# CAN 로그 파일 형식 (Log Format)

> 이 프로젝트가 읽는 CAN 로그 파일의 형식. Linux can-utils의 `candump -l`이 저장하는 형식과 같다.
> 같은 파일을 M3에서는 `bcm_sim --file`로 읽고, M5에서는 `canplayer`로 vcan0에 재생한다.

## 1. 한 줄 = 프레임 하나

```
(0.100000) vcan0 100#1027000000000000
└──┬─────┘ └─┬─┘ └┬┘ └──────┬───────┘
 타임스탬프  인터페이스 ID      데이터
```

| 필드 | 형식 | 설명 |
| --- | --- | --- |
| 타임스탬프 | `(초.마이크로초)` | 괄호 안에 소수점 있는 초. 예: `(0.100000)` = 0.1초 = 100ms. `candump`는 실제 시각(`(1697800000.123456)`)을 쓰고, 이 프로젝트의 시나리오는 **0초부터 시작하는 상대 시각**을 쓴다 |
| 인터페이스 | 영문자/숫자 | 어느 CAN 버스에서 받았는지. 예: `vcan0`, `can0`. 파서는 읽기만 하고 무시한다 |
| ID | **16진수 3자리** | Standard ID (`000` ~ `7FF`). `0x`는 붙이지 않는다 |
| `#` | | ID와 데이터 사이 구분자 |
| 데이터 | **16진수 0 ~ 16자리 (짝수)** | 2자리 = 1바이트. 글자 수 ÷ 2 = **DLC**. 대문자/소문자 모두 허용 (candump는 대문자로 쓴다) |

- 필드 사이는 **공백 한 칸**
- 줄 끝의 공백, 줄바꿈(`\n`, `\r\n`)은 무시한다

## 2. 건너뛰는 줄 (오류 아님)

| 줄 | 처리 |
| --- | --- |
| 빈 줄 | 건너뛴다 |
| `#`으로 시작하는 줄 | 주석으로 보고 건너뛴다 |

> ⚠️ **시나리오 파일(`data/scenarios/*.log`)에는 주석을 넣지 않는다.**
> can-utils의 `log2long`으로 확인해 보니 주석 줄을 만나면 이후 줄을 읽지 않았다. M5에서 `canplayer`로 그대로 재생하려면 순수한 candump 형식이어야 한다.
> 시나리오 설명은 `data/scenarios/README.md`에 따로 쓴다. (주석 허용은 손으로 만든 테스트 파일을 위한 것)

## 3. 정상 예시

| 줄 | 해석 |
| --- | --- |
| `(0.000000) vcan0 300#0203000000000000` | 0ms, 0x300, DLC 8 → 시동 ON, 기어 D |
| `(0.100000) vcan0 100#1027000000000000` | 100ms, 0x100, DLC 8 → 차속 100.00 km/h |
| `(0.200000) vcan0 200#11` | 200ms, 0x200, **DLC 1** → 운전석 + 트렁크 열림 (데이터 2자리 = 1바이트) |
| `(0.300000) vcan0 555#` | 300ms, 0x555, **DLC 0** (데이터 없음) → 문법상 정상, 디스패처가 무시 |
| `(1697800000.123456) can0 100#b80b000000000000` | 실제 candump 시각 + 소문자 데이터 → 차속 30.00 km/h |

## 4. 잘못된 예시 (파서가 거부)

| 줄 | 문제 |
| --- | --- |
| `vcan0 100#1027000000000000` | 타임스탬프 없음 |
| `0.100000 vcan0 100#1027000000000000` | 타임스탬프에 괄호 없음 |
| `(0.100000) 100#1027000000000000` | 인터페이스 없음 |
| `(0.100000) vcan0 1001027000000000000` | `#` 없음 |
| `(0.100000) vcan0 10#1027000000000000` | ID가 3자리가 아님 |
| `(0.100000) vcan0 1G0#1027000000000000` | ID에 16진수가 아닌 글자 |
| `(0.100000) vcan0 100#10G7` | 데이터에 16진수가 아닌 글자 |
| `(0.100000) vcan0 100#102` | 데이터 글자 수가 홀수 (1.5바이트?) |
| `(0.100000) vcan0 100#102700000000000000` | 데이터가 16자리 초과 (9바이트) |
| `(0.100000) vcan0 100#R` | Remote Frame → 이 프로젝트는 지원 안 함 (M1-1) |
| `(0.100000) vcan0 12345678#1027` | Extended ID (8자리) → 지원 안 함 |
| `(0.100000) vcan0 100##01027` | CAN FD 형식(`##`) → 지원 안 함 |

- 문법은 맞지만 값이 이상한 줄(예: `(0.1) vcan0 800#00` → ID가 0x7FF 초과)은 파서가 `CanFrame`으로 만든 뒤 `can_frame_is_valid()`에서 걸러진다

## 5. 파일 예시

```
(0.000000) vcan0 300#0200000000000000
(0.000000) vcan0 200#0000000000000000
(0.100000) vcan0 300#0203000000000000
(0.200000) vcan0 100#B80B000000000000
(0.300000) vcan0 200#0100000000000000
```
